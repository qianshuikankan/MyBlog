// ==================== 抽象基类：游戏对象（带Map统计） ====================
abstract class GameObject {
    protected int x, y, health, attackRange, attackPower;
    protected boolean countedAsDead = false;
    
    // 全局统计Map：类名 -> [生存数量, 死亡数量]
    protected static Map<String, int[]> globalStats = new HashMap<>();
    protected String className;
    
    public GameObject(int x, int y, int health) {
        this.x = x;
        this.y = y;
        this.health = health;
        this.attackRange = 0;
        this.attackPower = 0;
        this.className = this.getClass().getSimpleName();
        onCreated();
    }
    
    // 创建时更新统计
    protected void onCreated() {
        globalStats.putIfAbsent(className, new int[]{0, 0});
        globalStats.get(className)[0]++;
    }
    
    // 死亡时更新统计
    protected void onDestroyed() {
        if (globalStats.containsKey(className)) {
            globalStats.get(className)[0]--;
            globalStats.get(className)[1]++;
        }
    }
    
    public int getX() { return x; }
    public int getY() { return y; }
    public int getHealth() { return health; }
    public boolean isDestroyed() { return health <= 0; }
    
    protected double distanceTo(GameObject other) {
        int dx = this.x - other.x, dy = this.y - other.y;
        return Math.sqrt(dx * dx + dy * dy);
    }
    
    protected boolean canAttack(GameObject target) {
        return distanceTo(target) <= this.attackRange;
    }
    
    protected void takeDamage(int damage) {
        this.health -= damage;
        onDamageTaken();
    }
    
    protected void onDamageTaken() {
        if (isDestroyed() && !countedAsDead) {
            onDestroyed();
            countedAsDead = true;
        }
    }
    
    // 全局统计查询方法
    public static int getLivingCount(String className) {
        return globalStats.getOrDefault(className, new int[]{0, 0})[0];
    }
    
    public static int getDeadedCount(String className) {
        return globalStats.getOrDefault(className, new int[]{0, 0})[1];
    }
    
    public static Map<String, int[]> getAllStats() {
        return new HashMap<>(globalStats);
    }
    
    public abstract void move(int dx, int dy);
}

abstract class MobileUnit extends GameObject {
    public MobileUnit(int x, int y, int health, int range, int power) {
        super(x, y, health);
        this.attackRange = range;
        this.attackPower = power;
    }
    
    public void move(int dx, int dy) { this.x += dx; this.y += dy; }
    
    public void attack(GameObject target) {
        if (!canAttack(target) || target.isDestroyed()) return;
        target.takeDamage(calculateDamage(target));
    }
    
    protected int calculateDamage(GameObject target) { return this.attackPower; }
}

abstract class GameObject {
    protected int x, y, health, attackRange, attackPower;
    protected String type;  // 用字符串标识类型："RifleSoldier", "Dog", "MediumTank"...
    
    // 错误：在基类中处理所有子类的特殊攻击逻辑
    public void attack(GameObject target) {
        // 1. 检查距离
        double dist = Math.sqrt((this.x - target.x) * (this.x - target.x) 
                              + (this.y - target.y) * (this.y - target.y));
        if (dist > this.attackRange) {
            return; // 超出范围，攻击无效
        }
        
        // 2. 检查目标是否已死亡

| 违反原则               | 具体表现                                                     |
| :--------------------- | :----------------------------------------------------------- |
| **单一职责原则 (SRP)** | `attack()`方法承担了：距离判定+类型判断+伤害计算+特效播放+任务更新+掉落处理 |

| **里氏替换原则 (LSP)** | 建筑物（`GameBase`/`Barrack`）继承后，`attack()`行为异常（不能攻击但方法存在） |

## 核心问题分析

### 1. **基类知道太多（违反SRP）**
```
GameObject（基类）
    └── 知道 RifleSoldier 对战 Dog 要一击必杀
    └── 知道 Dog 对战 Soldier 要一口毙命  
    └── 知道 Tank 要有特殊音效
    └── 知道建筑物不能攻击（但还是要判断）
```

**正确设计**：基类只提供攻击**框架**，具体伤害规则由**子类**实现。

### 2. **类型判断地狱（违反OCP）**
```java
// 新增一个兵种，必须在这里加if-else
else if (this.type.equals("NewSoldier")) {
    // 新逻辑
}
```
每新增一个类型，就修改一次基类，**所有已有代码都要重新测试**。

### 3. **建筑物被迫有attack方法（违反LSP）**
```java
GameBase base = new GameBase(10, 10);
base.attack(someTarget);  // 能调用，但逻辑异常！
```

## ✅ 正确设计对比

| 错误设计                               | 正确设计                                                     |
| :------------------------------------- | :----------------------------------------------------------- |
| `GameObject.attack()` 处理所有类型判断 | `GameObject.attack()` 提供框架，`calculateDamage()`抽象给子类 |
| 用`String type`判断类型                | 用**多态**（`instanceof`或方法重写）                         |
| 基类知道子类特殊规则                   | 子类自己实现自己的规则                                       |
| 新增类型修改基类                       | 新增类型只需**新增子类**                                     |

## 正确代码片段

abstract class GameObject {
    // 一个Map管理所有类的统计
    protected static Map<String, int[]> globalStats = new HashMap<>();
    
    // 自动统计，子类无需关心
    protected void onCreated() {
        globalStats.putIfAbsent(className, new int[]{0, 0});
        globalStats.get(className)[0]++;  // 生存+1
    }
    
    protected void onDestroyed() {
        globalStats.get(className)[0]--;  // 生存-1
        globalStats.get(className)[1]++;  // 死亡+1
    }
    
    // 统一查询接口
    public static int getLivingCount(String className) {
        return globalStats.getOrDefault(className, new int[]{0,0})[0];
    }
}

// 子类完全不需要关心统计！
class Sniper extends Soldier {  // 新增兵种，零统计代码
    public Sniper(int x, int y) {
        super(x, y, 80, 15, 20);  // 只关注自身属性
    }
    // 统计自动完成！
}

## 🔴 违反了哪些原则

| 违反原则               | 具体表现                                                     |
| :--------------------- | :----------------------------------------------------------- |
| **开闭原则 (OCP)**     | 新增一个可攻击的类型（如`Sniper`），所有子类都要新增`attack(Xxx)`方法 |
| **里氏替换原则 (LSP)** | 父类`Soldier`定义`attack(GameObject)`，子类却定义一堆`attack(具体类型)`，无法多态替换 |
| **代码重复 (DRY)**     | 距离检查`canAttack()`、死亡判断`isDestroyed()`在每个重载方法里重复 |
| **类型爆炸**           | N个攻击者 × M个被攻击者 = N×M个方法组合                      |
| **无法运行时多态**     | 编译期确定调用的方法，无法根据实际对象类型动态判断           |

## 核心问题分析

### 1. **组合爆炸灾难**

```
攻击者类型：Dog, RifleSoldier, RPGSoldier, MediumTank, HeavyTank...（5种）
被攻击者类型：Dog, RifleSoldier, RPGSoldier, MediumTank, HeavyTank, GameBase...（6种）

需要的方法数：5 × 6 = 30个attack方法！

新增1个兵种 → 新增5个attack重载（每个攻击者都要加）
```

### 2. **编译期绑定，丧失多态**

```java
// 错误：无法运行时判断类型

// 被迫向下转型（危险！）

    ((Dog)attacker).attack((RifleSoldier)target);  // 丑陋且易错
}
```

### 3. **父类接口被架空**

```java
abstract class Soldier extends MobileUnit {
    // 父类定义了抽象方法
    public abstract void attack(GameObject target);
}

class Dog extends Soldier {
    // 子类却不实现父类方法，而是定义一堆重载！
    public void attack(Dog target) { ... }        // 不是override！
    public void attack(RifleSoldier target) { ... } // 不是override！
    // 父类方法空实现或抛异常
    public void attack(GameObject target) { 
        throw new UnsupportedOperationException(); 
    }
}
```

## ✅ 正确设计对比

| 错误设计                                          | 正确设计（参考前面代码）                            |
| :------------------------------------------------ | :-------------------------------------------------- |
| `attack(Dog)`、`attack(RifleSoldier)`... 30个重载 | 一个`attack(GameObject target)`，内部用**多态**判断 |
| 编译期确定攻击逻辑                                | 运行期根据`instanceof`或**双分派**确定逻辑          |
| 每个子类写N个重载                                 | 子类只实现`calculateDamage()`，描述自己的伤害规则   |
| "攻击谁"决定逻辑                                  | "我是谁"决定逻辑（自己的属性决定伤害计算）          |

    @Override
    protected int calculateSoldierDamage(GameObject target) {
