

# 1 字符集和编码

## 1 字符集

字符集（Character Set）是一个字符的集合，它定义了一组字符及其对应的编码值。字符集的主要作用是为每个字符分配一个唯一的标识符（通常是整数），以便在计算机系统中表示和处理这些字符。

### 2 字符集的编码

**字符集的编码**（Character Encoding）是指将字符集中的字符转换为字节序列的过程。编码方式定义了如何将字符集中的每个字符表示为计算机可以处理的二进制数据。不同的编码方式可以将同一个字符集中的字符表示为不同的字节序列。

### 3 字符集的主要特点

1. **字符集合**：字符集定义了一组字符，包括字母、数字、标点符号、特殊符号以及各种语言的字符。
2. **编码值**：每个字符在字符集中都有一个唯一的编码值，用于在计算机系统中表示该字符。
3. **固定性**：字符集一旦定义，其字符和编码值通常是固定的，不会轻易改变。

### 4 字符集中的码点

在字符集中，**码点**（Code Point）是指字符集中的字符所对应的唯一数值。码点是字符在字符集中的位置标识，用于唯一标识每个字符。

#### 码点的特点
1. **唯一性**：每个字符在字符集中都有一个唯一的码点。
2. **固定性**：码点在字符集定义后是固定的，不会改变。
3. **数值表示**：码点通常用十六进制表示，例如 `U+0041` 表示字符 'A' 的 Unicode 码点。

## 5 常见的字符集和编码

### 1. **ASCII**字符集和**ASCII**编码
- **公布时间**：1967年
- **包含的字符数量**：128个字符
- **码点范围**：`U+0000` 到 `U+007F`，共 128 个字符。
- **特点**：
  - ASCII（美国信息交换标准代码）是最基本的字符集，主要用于表示英语和西欧语言字符。
  - 使用7位二进制表示，每个字符占用1字节（8位），其中最高位通常用于扩展字符集。
  - 包含大小写英文字母、数字0-9、标点符号和一些控制字符。

- **示例**：
  - 字符 'A' 的 ASCII 码点是 `0x41`。编码也是`0x41`。
  - **“你” 的码点**：ASCII 不支持中文字符，因此“你”在 ASCII 中没有对应的码点，也没有编码。

### 2. **ISO-8859-1 (Latin-1)**字符集和 ISO-8859-1编码

- **公布时间**：1987年
- **包含的字符数量**：256个字符
- **码点范围**：码点范围是 **0x00 到 0xFF**，总共256个字符。其中，0x00到0x7F与ASCII相同，0x80到0x9F为控制字符，0xA0到0xFF为西欧语言字符。
- **特点**：
  - ISO-8859-1 是一个扩展的ASCII字符集，使用8位二进制表示，包含ASCII字符集的所有字符，并增加了西欧语言的字符。  
  - 包含拉丁字母、标点符号、特殊符号等。  
- **示例**：
  - 字符 'A' 的 ASCII SO-8859-1是 `0x41`。编码也是`0x41`。
  - 字符 'é' 的 ISO-8859-1 码点是  `0xE9`（十六进制）。编码也是`0xE9`。
  - **“你” 的码点**：ISO-8859-1不支持中文字符，因此“你”在 ISO-8859-1 中没有对应的码点，也没有编码。


### 3. **GB2312**字符集和**GB2312**编码
- **公布时间**：1980年
- **包含的字符数量**：7445个字符
- **码点范围**：`0x0000` 到 `0x7FFF`，实际使用的范围是 `0xA1A1` 到 `0xF7FE`。
- **特点**：
  - GB2312 是中国的第一个汉字编码标准，主要用于表示简体中文字符。
  - 使用双字节编码，每个字符占用2字节。
  - 包含6763个常用汉字和682个全角符号。
- **示例**：
  - 字符 'A' 的GB2312码点是 `0x41`。编码也是`0x41`。
  - **“你” 的码点**：在 GB2312 中，“你” 的码点是 `0xC4E3`。编码是 `0xC4 0xE3` 。
### 4. **GBK**字符集和**GBK**编码
- **公布时间**：1995年
- **包含的字符数量**：21886个字符
- **码点范围**：`0x0000` 到 `0xFFFF`，实际使用的范围是 `0x8140` 到 `0xFEFE`。
- **特点**：
  - GBK 是 GB2312 的扩展，完全兼容 GB2312，支持更多的中文字符，包括繁体字。
  - 使用双字节编码，每个字符占用2字节。
  - 包含21003个汉字和883个图形符号。
- **示例**：
  - 字符 'A' 的GBK码点是 `0x41`。编码也是`0x41`。
  - **“你” 的码点**：在 GB2312 中，“你” 的码点是 `0xC4E3`。编码是 `0xC4 0xE3` 。
### 5. **Unicode**字符集和对应的编码
- **公布时间**：1991年
- **包含的字符数量**：截至 Unicode 15.0 版本，Unicode 字符集定义了 **149,186 个字符**
- **码点范围**：`U+0000` 到 `U+10FFFF`，共 1,114,112 个码点。
- **特点**：
  - Unicode 是一个全球字符集，旨在容纳全球所有语言的字符。
  - 使用16位或32位二进制表示，每个字符占用2字节或4字节。
  - 包含几乎所有的字符，支持多种语言和符号。
- **示例**：
  - 字符 'A' 的Unicode码点是 `0x41`。
  - **“你” 的码点**：在 Unicode 中，“你” 的码点是 `U+4F60`。

#### **Unicode常见三种编码方式**

##### **1. UTF-8编码**

- **特点**：UTF-8 是一种可变长的编码方式，用 1 到 4 个字节表示一个字符。它向后兼容 ASCII，对于 ASCII 字符，UTF-8 使用 1 个字节表示。
- **示例**：
  - 字符 'A' 的 UTF-8 编码是 `0x41`（1 字节）。
  - “你” 的 UTF-16编码是`0xE4 0xB8 0xA6`（3 字节）

##### 2.UTF-16编码

- **特点**：UTF-16 是一种固定长度的编码方式，用 2 个字节表示一个字符。对于某些特殊字符（如某些 Unicode 扩展字符），可能需要 4 个字节（使用代理对）。
- **示例**：
  - 字符 'A' 的 UTF-16 编码是 `0x0041`（2 字节）。
  - 字符 '你' 的 UTF-16 编码是`0x4F60`（2 字节）。

##### **3. UTF-32**编码

- **特点**：UTF-32 是一种固定长度的编码方式，用 4 个字节表示一个字符。它确保每个字符的编码长度一致，但占用空间较大。
- **示例**：
  - 字符 'A' 的 UTF-32 编码是 `0x00000041`（4 字节）。
  - 字符 '你' 的 UTF-32 编码是 `0x00004F60`（4 字节）。

#### Unicode 的各种语言字符占用情况

Unicode 字符集涵盖了全球几乎所有语言的字符，以下是部分语言的字符占用情况：

| 语言/类别 | 字符数量（大致范围） | 备注 |
|:-----------|:----------------------|:-----|
| **ASCII**  | 128个字符             | 包括英文字母、数字和基本标点符号。 |
| **拉丁语系** | 约256个字符           | 包括西欧语言的字符，如法语、德语、西班牙语等。 |
| **西里尔语系** | 约256个字符           | 用于俄语、乌克兰语等。 |
| **希腊语**  | 约256个字符           | 包括希腊字母。 |
| **阿拉伯语** | 约256个字符           | 包括阿拉伯字母。 |
| **希伯来语** | 约256个字符           | 包括希伯来字母。 |
| **中文**   | 约7万个字符            | 包括简体和繁体汉字。 |
| **日文**   | 约7万个字符            | 包括平假名、片假名和汉字。 |
| **韩文**   | 约1.1万个字符          | 包括韩文字符。 |
| **其他语言** | 数量不等               | 如泰米尔语、梵文、缅甸语等。 |
| **特殊符号和表情符号** | 数量不断增加 | 包括数学符号、标点符号、表情符号等。 |

##### 说明
- Unicode 字符集的设计目标是涵盖全球所有语言的字符，因此其字符数量非常庞大。
- 中文、日文和韩文的字符存在重叠部分，大部分常见的汉字在中文、日文和韩文中的 Unicode 编码是相同的，但也有各自独特的部分。
- 随着 Unicode 版本的不断更新，字符数量还会继续增加，特别是表情符号和其他特殊符号。

# 2.乱码的表现和解决方法

Java 使用 Unicode 字符集来表示字符。具体来说，Java 的 `char` 类型是基于 Unicode 的，每个 `char` 占用 2 个字节（16 位），能够表示 Unicode 中的基本多文种平面（BMP）字符，即码点范围从 `U+0000` 到 `U+FFFF` 的字符。

对于超出 BMP 范围的字符（即码点大于 `U+FFFF` 的字符），Java 使用 **代理对**（Surrogate Pairs）来表示。一个代理对由两个 `char` 组成，分别称为高代理字符（High Surrogate）和低代理字符（Low Surrogate），每个代理字符占用 2 个字节，因此一个代理对占用 4 个字节。

## 1.乱码的根源

在 Java 中，乱码问题的根源是字符编码不一致：

```java
import java.io.UnsupportedEncodingException;

public class Demo {
	public static void main(String[] args) {
		try {
			String content = "大家好";
			testEncode(content, "gb2312", "gb2312");
			testEncode(content, "GBK", "GBK");
			testEncode(content, "GBK", "UTF-8");
			testEncode(content, "UTF-8", "GBK");
			testEncode(content, "UTF-8", "UTF-8");
		} catch (Exception e) {
			e.printStackTrace();
		}
	}

	public static void testEncode(String content, String srcEncode, String targetEncode)
			throws UnsupportedEncodingException {
		byte[] data = content.getBytes(srcEncode);
		String target = new String(data, targetEncode);
		System.out.println("srcEncode:" + srcEncode + " targetEncode:" + targetEncode + " : " + target);
	}
}
```

#### 示例代码
假设有一个字符串 "你好"，写入时使用 UTF-8 编码，读取时使用 GBK 编码。

```java
import java.io.BufferedReader;

        } catch (IOException e) {
            e.printStackTrace();
        }
    }

```

### 例子3
不同操作系统的默认编码可能不同，如果在编写代码时没有显式指定编码，可能会导致乱码。

```java
import java.io.*;
import java.nio.charset.Charset;

public class Demo {
    public static void main(String[] args) {
        String content = "你好";

        // 获取系统默认编码
        Charset defaultCharset = Charset.defaultCharset();
        System.out.println("系统默认编码: " + defaultCharset);
        
        // 使用系统默认编码写入,如果系统默认编码是 "GBK",这个例子就会有乱码错误

            writer.write(content);
        } catch (IOException e) {
            e.printStackTrace();
        }

        // 使用 UTF-8 编码读取
        try (BufferedReader reader = new BufferedReader(new InputStreamReader(new FileInputStream("example.txt"), "UTF-8"))) {
            String readContent = reader.readLine();
            System.out.println("读取的内容: " + readContent);
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}

```

## 3.避免乱码的解决方法

**核心思想：在char<->byte[]之间相互转换的时候 显示的指定编码方式**，保持编解码的一致性

### 1. **`String.getBytes(String charsetName)`**

将字符串转换为字节数组时，可以指定编码方式。

### 2.  **`new String(byte[] bytes, String charsetName)`**

从字节数组创建字符串时，可以指定编码方式。

### 3. **`InputStreamReader(InputStream in, String charsetName)`**
创建 `InputStreamReader` 时，可以指定输入流的编码方式。

### 4. **`OutputStreamWriter(OutputStream out, String charsetName)`**

创建 `OutputStreamWriter` 时，可以指定输出流的编码方式。

### 5. **`BufferedReader` 和 `BufferedWriter`**

在使用 `BufferedReader` 和 `BufferedWriter` 时，通常会包装 `InputStreamReader` 和 `OutputStreamWriter`，从而可以指定编码方式。

### 例子1 如何读写文本文件

```java
import java.io.BufferedReader;
import java.io.BufferedWriter;
import java.io.FileInputStream;
import java.io.FileOutputStream;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.util.Properties;

public class Demo {
    public static void main(String[] args) {
    	Properties properties = System.getProperties();
        for (String key : properties.stringPropertyNames()) {
            System.out.println(key + ": " + properties.getProperty(key));
        }        
        String fileEncoding = properties.getProperty("file.encoding");
        System.out.println("文件默认编码: " + fileEncoding);
        String filePath = "D:/temp/example.txt";
        // 以 UTF-8 编码写入文件
        try (BufferedWriter writer = new BufferedWriter(new OutputStreamWriter(new FileOutputStream(filePath), "UTF-8"))) {
            writer.write("你好");
        } catch (IOException e) {
            e.printStackTrace();
        }    
        // 以 UTF-8 编码写入文件
        try (BufferedReader reader = new BufferedReader(new InputStreamReader(new FileInputStream(filePath), "UTF-8"))) {
            String content = reader.readLine();
            System.out.println("读取的内容: " + content);
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

### 例子2 读取INI文件

```java
import java.io.*;

public class Demo {
    public static void main(String[] args) {
        String filePath = "D:/temp/example.txt"; // 文件路径
        // 使用 UTF-8 编码读取文件
        try (
            FileInputStream fis = new FileInputStream(filePath);
            InputStreamReader isr = new InputStreamReader(fis, "UTF-8");
            LineNumberReader reader = new LineNumberReader(isr)) {
            String line;
            while ((line = reader.readLine()) != null) {
                System.out.println("Line " + reader.getLineNumber() + ": " + line);
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

# 3总结

乱码根源在于byte[] <->char之间相互转换时候指定的编码方式不一致引起。最简单的办法就是

使用如下的方法：

```java
//字符串转换为byte[],这个方法定义在String里面:

public byte[] getBytes(String charsetName)

//byte[]转换为字符串,这个方法定义在String里面:
public String(byte bytes[], Charset charset)
```



而不要使用如下的方法 

```java
//字符串转换为byte[],这个方法定义在String里面:

public byte[] getBytes()

//byte[]转换为字符串,这个方法定义在String里面:
public String(byte bytes[])
```
